# Bilingual CSS compatibility

### CSS constraints (do not regress)

`cssclasses` land on the whole `.markdown-source-view` / `.markdown-preview-view` container, and third-party plugins mount their UI inside that same container. Three collisions have already caused real breakage:

1. **Selector scope.** The Editing Toolbar color palette is literally a `<table class="x-color-picker-table">` whose swatches are colored by `<td style="background-color:...">` inline styles, and it lives inside `.markdown-source-view`. A broad `.editable-bilingual table td { background: transparent !important }` wipes the swatches out (colors invisible; the user can only blind-pick) and also wrecks the palette layout. Every table rule in this snippet must be scoped to the note body — `.editable-bilingual :is(.cm-content,.markdown-preview-sizer) table ...` — never to the bare container.
2. **Cell padding.** In Live Preview the table is an embedded mini-editor: Obsidian sets `td, th { padding: 0 }` and puts the cell padding on `.table-cell-wrapper`. Padding added to `td`/`th` creates a ~1.4rem click dead zone along each cell edge: clicks there miss the editable `.table-cell-wrapper`, fall through to the outer editor, and drop the cursor after the table block (symptom: "can't click into the content, the cursor jumps to the next line"). Keep `padding: 0` on `td`/`th`, and put the padding on `.table-cell-wrapper` for Live Preview and on `td`/`th` only for reading view (which has no wrapper). The wrapper already carries Obsidian's own `var(--size-2-2)` / `var(--size-4-2)` padding, so add the snippet's padding with `calc()` — otherwise the gutter and header row shrink and the layout visibly changes.
3. **Line height & wrapping (text jumps on click).** A Live Preview cell has two states. Unfocused it is *rendered*: plain text sitting directly in `.table-cell-wrapper`, inheriting `line-height` / `white-space` from `td`. On focus Obsidian hides that wrapper and appends a **second** `.table-cell-wrapper` containing a real CodeMirror mini-editor. That editor does **not** inherit from `td` — it reads Obsidian's own variables, `--table-line-height` (default `1.3`) on `.cm-table-widget .cm-scroller` and `--table-white-space` (default `break-spaces`) on `.cm-table-widget .cm-content.cm-lineWrapping`. Because this snippet sets `td { line-height: 1.8; white-space: normal }`, the two states disagree: clicking drops the line height from 28.8px to 20.8px and switches wrapping from `normal` to `break-spaces` (which also produces an extra wrapped line), so the row height collapses, the text slides up, and the caret stays where the mouse was (symptom: "after selecting, the text shrinks upward and the cursor is misplaced"). Fix by aligning the editor to the rendered state — set `--table-line-height: 1.8` and `--table-white-space: pre-wrap` on `.editable-bilingual`. Do **not** try to fix it by setting `white-space: normal` on the editor's `.cm-content`: CodeMirror needs a space-preserving value to measure caret positions, and changing the static wrapper to `break-spaces` instead would silently reflow every note.

Apply the same three rules to any new snippet for this vault. When a user reports "a plugin popup renders blank/colorless", "table cells can't be clicked, the cursor jumps", or "the text shrinks upward when I select" **only in my bilingual notes**, check these three collisions first.


### Source tables with more than two columns

The existing snippet assigns 50% cell widths and draws a divider after the first column. Genuine source tables with three or more columns must retain their own columns and header labels; do not force them into a two-column prose translation pair. In bilingual mode use bilingual text within the original cells. Inspect these tables for width and divider anomalies; any CSS adjustment must preserve the three compatibility constraints above.
